# Product Context

## Product Name
Working title: Student Developer Community App

## What We Are Building
A focused social/community app for engineering students to share projects, ask doubts, collaborate, and build their developer identity.

This is not meant to be generic social media. It should be useful for student developers who are actively learning, building, participating in hackathons, and preparing for internships.

## Initial Target Users
Phase 1 users:
- BTech / engineering students
- Students in our own college
- Students interested in coding, projects, hackathons, internships, and tech learning

Secondary users:
- Seniors with experience
- Juniors seeking help
- Coding club members
- Students looking for collaborators

## Main Problem
Students do not have a focused platform inside college to:
- share what they are building
- ask technical doubts
- get feedback
- discover other student developers
- build visible proof of skill

LinkedIn feels too formal.
WhatsApp and Discord are messy and unstructured.
Existing social apps are too broad.

## Product Vision
To become the go-to platform for engineering students to showcase work, collaborate, learn publicly, and grow as developers, starting from one college and expanding later.

## Product Principles
- Keep it useful, not flashy
- Make posting easy and fast
- Encourage interaction, not passive scrolling
- Focus on project sharing, doubts, and student growth
- Prioritize retention over feature count
- Build small, test early, improve fast

## MVP Scope
The MVP should include:

1. Authentication
- Google login or email login
- secure and simple onboarding

2. Onboarding/Profile Setup
- name
- year
- branch
- skills/tags
- optional bio

3. Feed
- view posts
- latest/relevant posts
- simple clean UI

4. Create Post
Post types:
- Project Update
- Doubt / Question
- Achievement
- Idea / Learning

5. Interactions
- like
- comment

6. Profile
- user details
- skills
- posts history
- aura points

7. Q&A Style Use
- users can ask doubts through posts
- others can answer through comments

8. Basic Aura / Gamification
- points for posting
- points for commenting
- points for answering
- simple visible progress

## Not In MVP
Do NOT prioritize these right now:
- direct messaging/chat
- reels/video-heavy features
- advanced notifications
- recruiter dashboard
- paid features
- full leaderboard system
- collaboration matching engine
- advanced search/filtering
- too much customization

## Launch Strategy
Phase 1:
- launch in our own college
- start with active students who code/build
- onboard friends, classmates, juniors, and selected seniors

Phase 2:
- improve based on usage
- increase activity inside college

Phase 3:
- expand to other colleges after retention is good

## Success Metrics
We should measure:
- daily active users
- weekly active users
- number of posts per day
- comments per post
- percentage of users who return
- number of active creators

## Important Notes for AI/Developers
- This product is for student developers, not for everyone.
- Product usefulness matters more than visual complexity.
- New features should only be added if they improve engagement or retention.
- Keep the architecture simple and maintainable.
- Always think phase-wise.
